## 1. Состояние query, позиционный embedding и бокс

У кандидата три разных набора чисел:

| Величина | Размер | Роль |
|---|---|---|
| Состояние query `q` | 64 | Собранные признаки; меняется при обработке изображения |
| `query_position` | 64 | Обучаемый embedding слота, добавляемый при вычислении attention |
| Бокс `(cx, cy, w, h)` | 4 | Явная геометрическая оценка |

В нашем коде начальное состояние, query position и logits начального бокса — отдельные параметры. Query position не является координатой и не вычисляется из бокса.

Начальные параметры общие для изображений. После первого чтения состояние зависит от изображения через взятые признаки. Номер кандидата не закреплён за конкретным человеком или номером GT.

## 2. Что такое точка выборки и зачем интерполяция

Точка выборки — положение на карте, в котором берётся вектор признаков. Она может лежать между центрами ячеек. Билинейная интерполяция смешивает значения четырёх соседей, поэтому небольшое перемещение точки обычно меняет прочитанный вектор.

В примере 2А один канал содержит:

```text
          x = 0   x = 1
y = 0       1       3
y = 1       5       7
```

В точке `(0.35, 0.65)` сначала интерполируем по x: сверху получаем 1.7, снизу 5.7. Затем по y:

```text
1.7 + 0.65 × (5.7 − 1.7) = 4.3
```

Здесь `f(x, y) = 1 + 2x + 4y`, поэтому производные по координатам равны 2 и 4. Detection loss может пройти через признаки к координатам и далее — к сети, которая их предсказала.

### Три записи одной координаты

Индекс 0 обозначает центр первого пикселя. Этот центр находится на расстоянии половины пикселя от левого края. Для карты ширины W:

```python
p_x = (x + 0.5) / W
g_x = 2 * p_x - 1
x = W * p_x - 0.5
```

`x` — координата в системе центров пикселей; `p_x` — доля ширины карты; `g_x` — значение для `grid_sample` с `align_corners=False`.

| Точка на карте ширины 2 | x | p_x | g_x |
|---|---:|---:|---:|
| Центр первого пикселя | 0 | 0.25 | −0.5 |
| Между центрами | 0.5 | 0.5 | 0 |
| Центр второго пикселя | 1 | 0.75 | 0.5 |

Пример `(0.35, 0.65)` превращается в `p=(0.425, 0.575)` и `g=(-0.15, 0.15)`. В `grid_sample` передаётся g, результат — те же 4.3.

При `align_corners=False` значения −1 и +1 соответствуют внешним краям карты. Для y используется H, для x — W; grid хранит пары `(x, y)`, а тензор карты имеет пространственные оси `(H, W)`. Определение координат и padding приведено в [документации PyTorch](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.grid_sample.html).

В однородной области координатный градиент равен нулю: движение не меняет признак. Далеко за изображением с zero padding он также равен нулю. Поэтому произвольная инициализация далёкими точками может мешать обучению.

## 3. Шесть точек и четыре головы

Шесть — выбранный бюджет одной головы для одного query на одном слое. Это не число объектов и не набор размеченных частей объекта.

Из вектора `z = state + query_position` линейные головы предсказывают смещения и веса. На одну голову приходится 12 чисел смещений и 6 logits весов; на четыре — 48 и 24 соответственно.

Относительно опорного бокса координаты получаются так:

```python
px = cx + 0.5 * w * dx
py = cy + 0.5 * h * dy
```

Смещение `(0, 0)` даёт центр, `(1, 0)` — правую границу бокса, `(2, 0)` — точку за ней. Это уже нормированные координаты p, поэтому для `grid_sample` нужен только перевод `2 * p - 1`.

Шесть весов после softmax определяют вклад шести точек. Это другие веса, чем четыре коэффициента билинейной интерполяции внутри каждой точки.

### Что означает «каждая голова читает 16 каналов»

В каждой ячейке карты лежат 64 числа. Value projection — свёртка 1×1, которая обучаемо смешивает эти каналы и снова выдаёт 64 числа. Затем они делятся на четыре группы:

```text
каналы  1–16 → голова 1
каналы 17–32 → голова 2
каналы 33–48 → голова 3
каналы 49–64 → голова 4
```

Каждая голова берёт свои 16 каналов в шести выбранных местах и складывает шесть векторов с весами. Получается один вектор длины 16. Объединяем четыре головы в 64 числа и применяем output projection.

Поскольку value projection смешивает все входные каналы, у групп нет заранее заданного смысла. Головы могут научиться извлекать разные признаки и использовать разные точки.

## 4. Что именно замораживается в fixed

В `fixed` заморожены параметры головы относительных смещений. Веса точек, начальные боксы, queries и проекции продолжают обучаться. Поэтому абсолютные точки могут двигаться в процессе обучения за счёт начальных боксов.

После обучения в этой версии координаты одинаковы для разных изображений и всех слоёв: смещения фиксированы, reference остаётся начальным. В `learned` первый reader тоже получает состояние без информации об изображении, но поздние readers могут выбирать координаты в зависимости от предыдущего чтения.

В `global` уже первое распределение attention зависит от изображения через ключи. В sampling веса предсказываются непосредственно из query; матрица сходств со всеми пикселями отсутствует.

## 5. Зачем возвращать предсказанный бокс в attention

Бокс задаёт центр и масштаб точек. Если модель предсказала более точный бокс, следующий слой может собирать признаки уже относительно него:

```text
признаки → состояние query → бокс → новая область выборки → следующие признаки
```

В `learned` все readers используют исходный бокс. В `refine` reader использует бокс предыдущей стадии. Выходные боксы уточняются в обоих вариантах:

```python
new_box = sigmoid(logit(previous_box) + correction)
```

Нулевая поправка сохраняет бокс. Для компоненты 0.2 поправка `log(2)` даёт 1/3: удваивается отношение `b / (1 - b)`. Sigmoid удерживает центр и размер в (0, 1), но не обязательно удерживает углы внутри изображения.

`detach` между стадиями отключает градиент через предыдущие координаты. Путь через состояние query остаётся. Промежуточные losses отдельно обучают box heads.

Ошибка геометрии может направить следующий reader в неудачную область. В loss нет условия, что IoU следующего слоя обязан быть выше предыдущего.

## 6. Почему несколько уровней помогают маленьким объектам

Объект шириной 12 пикселей занимает 1.5 ячейки C3, 0.75 ячейки C4 и 0.375 ячейки C5. На грубой карте мало пространственных отсчётов для локализации.

В `multi` каждая голова использует по две точки на C3/C4/C5 вместо шести на C5. Уровни назначены кодом, координаты и веса обучаются. Softmax общий по всем шести точкам: две точки на уровень не означают треть общего веса.

Уровни различаются разрешением и содержанием признаков. Поэтому рост метрики при добавлении C3/C4 нельзя приписать только размеру сетки.

Наш бюджет — шесть точек на голову **суммарно по уровням**. В официальном Deformable DETR параметр числа точек задаётся на каждый уровень. Сравнивая формулы и параметры, нужно учитывать это отличие. [Официальный attention module](https://github.com/fundamentalvision/Deformable-DETR/blob/main/models/ops/modules/ms_deform_attn.py).

## 7. Почему первый слой уже может предсказывать объекты

Первый decoder layer получает признаки после глубокой сети ResNet18, а его выход прямо обучается classification и box losses. Поэтому хороший ранний бокс возможен.

В нашем порядке операций первый self-attention обрабатывает ещё не зависящие от изображения состояния. После cross-attention состояния уже содержат признаки, и self-attention следующего слоя может учитывать, что прочитали другие кандидаты.

Это свойство конкретной архитектуры и обучения. Хорошие промежуточные предсказания не гарантированы для любого трансформера. В оригинальном DETR влияние глубины decoder и дубликатов рассмотрено в [§4.2](https://arxiv.org/html/2005.12872v3#S4.SS2).

## 8. Что можно заключить из экспериментов

Каждый вариант обучался 600 шагов с batch 8: 4800 предъявлений изображений, эквивалент примерно 25 эпох на Shapes и 50 на COCO128/person. Во всех вариантах backbone заморожен.

Средний AP50 на Shapes: fixed 0.217, learned 0.213, refine 0.195, multi 0.769. Отдельный выигрыш смещений и feedback при данном бюджете не подтверждён. Это не сравнение полностью обученных DETR и Deformable DETR.

AP50 использует IoU ≥ 0.5, AP75 — IoU ≥ 0.75. Это пороги геометрического перекрытия. Порог уверенности 0.3 в рисунках не используется при вычислении AP: метрика получает все 32 predictions.

Один хороший query не оценивает всю модель. Для сравнения стадий нужна метрика по всей validation-выборке после каждого слоя, а для сравнения скорости сходимости — несколько бюджетов обучения.

## 9. Статьи: маршрут от DETR к denoising

| Материал | Что читать | Какой вопрос углубляет |
|---|---|---|
| [DETR — Carion et al., ECCV 2020](https://arxiv.org/abs/2005.12872) | §3.1: matching и set loss; §3.2: decoder; §4.2: абляции глубины | Как обучать набор кандидатов и зачем несколько стадий |
| [Deformable DETR — Zhu et al., ICLR 2021](https://arxiv.org/abs/2010.04159) | §4.1: attention; §4.2 и Appendix A.4: refinement и two-stage | Как устроено разреженное чтение и где используется геометрия |
| [GIoU — Rezatofighi et al., CVPR 2019](https://arxiv.org/abs/1902.09630) | Определение охватывающей области и примеры непересекающихся боксов | Откуда берётся сигнал, когда IoU равен нулю |
| [DN-DETR — Li et al., CVPR 2022](https://arxiv.org/abs/2203.01305) | Ветка восстановления зашумлённых GT и attention mask между группами queries | Как упростить обучение при нестабильном matching |
| [DINO — Zhang et al., ICLR 2023](https://arxiv.org/abs/2203.03605) | Contrastive denoising, mixed query selection, look forward twice | Что добавили к геометрическим queries и denoising |

Denoising в DN-DETR — дополнительная задача обучения: из зашумлённых GT восстанавливаются исходные объекты. При inference GT не нужны. Ветвь с известным соответствием отделяется от обычных matching queries attention mask, чтобы последние не получали ответы из разметки. DINO здесь — детектор, не одноимённый метод self-supervised обучения признаков.

- [Deformable transformer](https://github.com/fundamentalvision/Deformable-DETR/blob/main/models/deformable_transformer.py): reference points, уточнение боксов и `detach`.
- [COCOeval](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py): ранжирование predictions, matching при IoU-порогах и усреднение AP.
