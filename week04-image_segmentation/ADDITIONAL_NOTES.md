## 1. Класс пикселя, маска класса и маска экземпляра

Semantic segmentation присваивает каждому пикселю класс. Два круга одного класса получают одну метку, даже если они расположены далеко друг от друга. Instance segmentation должна дополнительно различать сами объекты.

Поэтому последний слой `Conv2d(D, C + 1, 1)` в нашей semantic-модели выдаёт C каналов классов объектов и один канал фона. В set-модели `Conv2d(D, N, 1)` выдаёт N кандидатов на маски; класс каждого кандидата предсказывается отдельно. N ограничивает число выходных объектов, но не задаёт число классов.

В ноутбуке сначала используются 100 каналов для разбора операции. В парных обучениях оставлены 8 кандидатов при максимуме в три объекта — это отдельная конфигурация маленького опыта.

## 2. Зачем mask pooling

Для классификации маски нужен вектор, описывающий соответствующий объект. Пусть `F[x, y]` — вектор признаков пикселя, а `m_i[x, y]` — вероятность принадлежности кандидату i. Тогда:

$$
z_i=\frac{\sum_{x,y}m_i(x,y)F(x,y)}
{\max(\sum_{x,y}m_i(x,y),\varepsilon)}.
$$

Это среднее с весами: пиксели, на которые маска даёт большой вес, сильнее влияют на описание кандидата.

В ручном примере признаки первого объекта равны `[1, 0]`, второго — `[0, 1]`. Global pooling даёт один вектор `[0.5, 0.5]`. Если передать его в один и тот же классификатор для обоих кандидатов, ответы совпадут. Pooling по разным маскам даёт разные векторы.

Mask pooling нужен свёрточному baseline для получения отдельных описаний кандидатов. В query-модели таким описанием может служить само обновлённое состояние query.

## 3. Почему нельзя назначить первый канал первому объекту

Порядок объектов в разметке произволен. Если поменять две GT-маски местами, изображение и задача не изменятся. Loss с фиксированным назначением по индексу при этом может измениться.

Hungarian matching ищет разные кандидаты для всех GT, минимизируя суммарную стоимость. В семинаре стоимость включает:

- `−p(class)`: соответствие класса;
- BCE: попиксельные ошибки вероятностей;
- Dice loss: перекрытие относительно площади масок.

Matching вычисляется без градиента. После выбора пар соответствующие predictions участвуют в дифференцируемом loss. Кандидаты без пары получают класс no-object; отдельный mask loss для них не считается. Поэтому свободному кандидату не обязательно иметь пустую маску, но он должен иметь малую вероятность класса объекта.

BCE и Dice дают разные сигналы. При маленьком объекте усреднённая по всей картинке BCE может слабо реагировать на его пропуск. Dice не получает выигрыша от большого числа правильно распознанных фоновых пикселей:

$$
\mathcal L_{\rm Dice}
=1-\frac{2\sum m t+1}{\sum m+\sum t+1}.
$$

В matching применяется `−p`, а при обучении класса — `−log p`. Коэффициенты 2/5/5 задают относительный вес классификации и двух mask-слагаемых. Это настройки objective, а не требования венгерского алгоритма.

One-to-one назначение действует при обучении. Оно создаёт штраф за лишних кандидатов, но не гарантирует отсутствия дубликатов на новых изображениях.

## 4. Что дают queries, если уже можно предсказывать N масок

Свёрточный вариант уже решает set-prediction задачу. Его маски зависят от изображения через признаки F, но фильтр каждого канала фиксирован после обучения:

$$
\ell_i(x,y)=w_i^\top F(I,x,y).
$$

В query-модели сам фильтр становится результатом обработки изображения:

$$
q_i^{(t+1)}=\operatorname{DecoderLayer}(q^{(t)},F)_i,\qquad
e_i(I)=\operatorname{MLP}(q_i^{(T)}),\qquad
\ell_i(x,y)=e_i(I)^\top F(I,x,y).
$$

У каждого кандидата появляется состояние, которое можно несколько раз обновить. Cross-attention собирает признаки изображения; self-attention связывает состояния кандидатов. Начальные queries — параметры модели, общие для изображений.

Сами по себе обучаемые embeddings ещё не делают фильтр динамическим. Если embedding не получает информацию об изображении, после обучения он остаётся фиксированным.

В ноутбуке подмена `e_i(I)` на embedding другого изображения меняет только способ построения финальных масок. Это проверка того, использует ли обученная модель зависимость фильтра от изображения. Для сравнения качества фиксированных и динамических фильтров нужны отдельные обучения; они приведены рядом.

## 5. Предыдущая маска ограничивает следующее attention

В masked attention разрешённой области соответствует добавка 0 к attention scores, запрещённой — `−∞`:

$$
A=\operatorname{softmax}\left(QK^\top/\sqrt d+M\right).
$$

Веса запрещённых позиций становятся нулевыми; оставшиеся перенормируются. В используемом `nn.MultiheadAttention` значение `True` булевой маски означает запрет. Это соглашение конкретного API.

Маску перед порогом приводим к разрешению memory. Порог и `detach` убирают путь градиента через сам выбор разрешённых позиций. Маска всё равно обучается своим loss и зависит от обучаемых pixel features и query.

Если query запрещает все позиции, softmax от одних `−∞` не определён. Реализация вновь разрешает всю строку, чтобы кандидат мог получить признаки и изменить маску. Этот fallback разобран отдельным примером.

Булевая маска сама по себе не уменьшает размер dense-матрицы `queries × pixels`. Ускорение требует реализации, которая действительно пропускает вычисление запрещённых связей.

## 6. Ранние выходы и масштабы

В нашей модели начальная маска вычисляется до первого attention. Её фильтр ещё фиксирован относительно изображения, но pixel features уже зависят от него. Поэтому начальная маска может оказаться хорошей.

Auxiliary losses дополнительно обучают промежуточные состояния. В сегментационном notebook итоговый training loss **суммирует** losses стадий. Отдельный опыт с градиентами использует их **среднее**, чтобы не спутать изменение направления с простым добавлением слагаемых. Это разные сравнения.

Memory выбирается по слоям на strides 32 → 16 → 8. Более поздний слой читает более подробную сетку, а итоговые mask logits во всех вариантах строятся на stride 4. Меняется источник информации для query, а не размер выходной карты маски.

## 7. Точки для loss и точки для attention

В этом семинаре точки используются, чтобы считать matching и mask loss по части пространственных позиций:

- matching использует общие случайные координаты для всех пар масок одного изображения;
- mask loss использует смесь неуверенных и равномерных точек для каждой matched-маски.

Неуверенность определяется близостью logits к нулю, то есть вероятности к 0.5. Уверенно ошибочная область может не попасть в такой отбор, поэтому сохраняется случайная часть.

Это не те sampling points, которые query предсказывает для deformable attention в семинаре по детекции. Здесь точки выбирает процедура оценки loss; в детекции точки задают, какие признаки получает состояние query.

## 8. Как интерпретировать метрики

Высокий semantic mIoU возможен даже при плохом разделении экземпляров: объединение двух кругов закрашено правильно, но отдельные круги не найдены. Instance precision учитывает лишние predictions, recall — пропущенные GT.

В ноутбуке instance-метрики используют фиксированные пороги score 0.4 и IoU 0.5. AP строится по кривой precision–recall при изменении порога уверенности; наши precision/recall описывают одну точку этой кривой.

Сравнение двух архитектур, вмешательство в один checkpoint и показ выбранного query отвечают на разные вопросы. Удачный частный пример не заменяет метрику по всей validation-выборке. Разброс по трём seeds на одном split оценивает влияние инициализации и порядка batch, но не неопределённость на всех возможных новых изображениях.

## 9. Статьи: что читать и зачем

Основной порядок: **DETR → MaskFormer → Mask2Former**. U-Net помогает разобрать pixel decoder, PointRend — выбор точек.

| Материал | На что смотреть | Связь с ноутбуком |
|---|---|---|
| [U-Net — Ronneberger et al., 2015](https://arxiv.org/abs/1505.04597) | Схема encoder/decoder и skip connections | Как совместить контекст глубоких признаков и пространственные детали |
| [DETR — Carion et al., 2020](https://arxiv.org/abs/2005.12872) | §3.1: set loss; §3.2: object queries и auxiliary losses | Почему число кандидатов фиксировано, а число объектов переменно |
| [MaskFormer — Cheng et al., 2021](https://arxiv.org/abs/2107.06278) | Представление результата как масок с классами, mask embeddings и pixel embeddings | От попиксельных классов к набору масок |
| [Mask2Former — Cheng et al., CVPR 2022](https://arxiv.org/html/2112.01527v3) | §3.2: masked attention и high-resolution features; §3.3: training efficiency; §4.4: абляции | Зачем ограничивать внимание, менять уровень memory и считать loss по точкам |
| [PointRend — Kirillov et al., CVPR 2020](https://arxiv.org/abs/1912.08193) | Выбор неоднозначных точек и уточнение сегментации | Как направлять вычисления в сложные пространственные области |

В полной Mask2Former pixel decoder использует multi-scale deformable attention. Наш U-Net pixel decoder — учебное упрощение. PointRend отдельно уточняет предсказания по точкам; notebook использует выбор точек для loss и не реализует PointRend целиком.

Реализации для сопоставления с кодом:

- [Mask2Former decoder](https://github.com/facebookresearch/Mask2Former/blob/main/mask2former/modeling/transformer_decoder/mask2former_transformer_decoder.py): построение `attn_mask`, fallback и порядок обновлений.
- [Matcher](https://github.com/facebookresearch/Mask2Former/blob/main/mask2former/modeling/matcher.py): стоимость пар и point sampling для назначения.
- [Criterion](https://github.com/facebookresearch/Mask2Former/blob/main/mask2former/modeling/criterion.py): no-object, BCE/Dice и промежуточные losses.
